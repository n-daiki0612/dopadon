# 駿河どん！

静岡の海の幸を収穫し、海鮮丼を作って販売し、道具を強化するブラウザゲームです。React + Vite + JavaScript + CSSで実装し、バックエンド・外部API・認証は使用しません。

## 起動

Node.js 22.12以上（検証環境: 24.14.1）を用意してください。

```sh
npm install
npm run dev
```

表示されたURL（通常 http://127.0.0.1:5173 ）をブラウザで開きます。PowerShellでスクリプト実行が制限される場合は `npm.cmd install`、`npm.cmd run dev` を使用してください。

```sh
npm test         # Node.js標準テストランナーによるロジックテスト
npm run build   # dist/ に本番ビルドを生成
npm run preview # ビルド済みゲームを確認
```

スマートフォンから同じLANで試す場合は `npm run dev -- --host 0.0.0.0` を使用し、PCのLANアドレスと表示されたポートにアクセスします。環境によってファイアウォールの設定が必要です。

### Windowsの依存キャッシュ書き込みエラー

サンドボックスや別アカウントで作られた `node_modules/.vite` への書き込み拒否を避けるため、`vite.config.js` でキャッシュをプロジェクト直下の `.vite-cache` に配置しています（Git管理対象外）。設定変更後は以前の開発サーバーを Ctrl+C で止め、通常のターミナルで `npm.cmd run dev` を再実行してください。既存の `node_modules` やキャッシュを削除する必要はありません。

`node scripts/verify-dev.mjs` で開発サーバーを一時的に5183番ポートで起動し、トップページ・JSX・最適化したReact/React DOMのHTTP配信を検証できます。検証終了後はサーバーを停止します。2026-10-24に4リクエストすべてHTTP 200、依存生成エラーなしを確認しました。これはブラウザ実操作の検証とは別です。

## 遊び方・初期仕様

1. 「漁にでる」で泳ぐ魚をクリック、またはタップして収穫します。
2. 「海鮮丼」で＋・−ボタンで食材を選び、「海鮮丼を作る」を押します。
3. 完成した丼を「販売する」と食材価格の合計が所持金に加算されます。
4. 「ショップ」で集魚セットを強化し、漁へ戻ります。

初期所持金・食材は0です。桜エビ50円、シラス70円、マグロ150円。丼は1尾から個数制限なしで作成でき、未販売の丼は1杯まで。米の費用・時間制限・販売ボーナスはありません。プレビューは各種類5個まで表示しますが、価格と食材消費には全数量を反映します。

魚の抽選比率は45:35:20、初期間隔1500ms。漁画面に入ると最初の魚が出現し、その後は一定間隔で出現します。泳ぐ時間は11秒、画面上限は24匹。画面を離れると泳いでいる魚を消し、漁以外の画面では出現しません。所持品・丼・お金は画面を切り替えても残ります。リロードすると初期化されます。

強化は最大レベル5。価格は `round(200 × 1.7^現在レベル)`、間隔は `max(500, round(1500 × 0.85^レベル))` msです。設定は `src/game/constants.js` に集約しています。

①はfishing、②はdonburi、③はshopと経済ロジックを担当します。各画面は `useGame()` を通して共通状態を読み、操作を呼び出します。他画面の内部状態に依存しません。共通ロジック・App・FishArt・CSS・依存パッケージの変更は先に担当者間で共有してください。CSSの画面別規則は必要に応じて各担当フォルダーへ分割できます。仕様・定数・操作名を変更する際はテストとREADMEも同時に更新してください。

## 共通状態

```js
{
  money: 0,
  inventory: { sakuraebi: 0, shirasu: 0, maguro: 0 },
  upgrades: { lure: 0 },
  bowl: null, // または { ingredients: { sakuraebi, shirasu, maguro }, price }
  activeFish: [], // { id: 個体UUID, species: 魚種ID, top: %, direction: 1 | -1 }
  stats: { caught: 0, sold: 0, earned: 0 }
}
```

React Context + useReducerで管理します。選択中の食材は海鮮丼画面のローカル状態で、画面を離れると選択だけリセットされます。完成した丼は共通状態に保持します。

## インターフェース

`useGame()` は `state` と次の関数を返します。関数はdispatchのみを行い、結果は次のレンダーのstateに反映されます。

| 操作 | 引数・効果 |
| --- | --- |
| `catchFish(fishId)` | 魚種IDではなく出現中の**個体ID**。存在する魚を消し、対応食材を1個追加 |
| `createBowl(ingredients)` | `{ sakuraebi: 2, maguro: 1 }` のような個数マップ。省略種は0。検証後に食材を消費し丼を作成 |
| `sellBowl()` | 丼が存在するときだけ価格を加算し、丼を削除 |
| `buyUpgrade(upgradeId)` | 現在は `'lure'` のみ。残金・最大レベルを検証して購入 |
| `spawnFish(fish)` | 漁画面内部用。UUIDを付けた魚を登録 |
| `removeFish(fishId)` | 漁画面内部用。CSS animationendで退出した個体を削除 |
| `clearFish()` | 漁画面内部用。アンマウント時に泳いでいる魚だけ削除 |

Reducerが負数・小数・未知の食材・所持数超過・空の丼・丼の上書き・資金不足・上限超過を拒否します。収穫時に個体を削除し、販売時に丼を削除するため、連続クリックも二重計上されません。魚種IDと個体IDを混同しないでください。出現タイマーは強化レベルから間隔を再計算します。

## デザイナー向け画像差し替え

| ファイル | 推奨サイズ | 用途 |
| --- | --- | --- |
| `public/assets/sakuraebi.png` | 256×160px、透明背景 | 桜エビ |
| `public/assets/shirasu.png` | 256×160px、透明背景 | シラス（群れの絵でも可） |
| `public/assets/maguro.png` | 256×160px、透明背景 | マグロ |

左向きの絵を推奨します。右向きに泳ぐときはCSSで反転します。ファイルを置いてページを再読み込みするだけで全画面の表示が変わります。欠落・読込失敗時は種類別のサイズ・色を持つ絵文字に切り替わり、画像がなくても全機能を利用できます。シラスは白い群れ、マグロは大きな青い魚、桜エビはエビで区別します。海・海底・丼はCSSで描画しているため画像不要です。音声は未使用です。
